ABC cocok untuk keluarga kelas yang saya kendalikan dan perlu berbagi kode, karena kewajiban method ditegakkan saat objek dibuat; Tugas 3 memperlihatkan harganya, yaitu menambah satu method abstrak langsung mematahkan semua plugin. Protocol cocok untuk kontrak kecil, termasuk untuk kelas yang tidak bisa diubah, tetapi isinstance() hanya memeriksa nama method sehingga perlu dilengkapi pemeriksa tipe statis dan pengujian. Registry, dekorator, dan autodiscovery membuat metode pembayaran baru cukup berupa satu berkas tanpa mengubah inti.
Kesulitan yang saya temui: memahami bahwa kesesuaian Protocol saat runtime tidak mencakup tanda tangan method, mengingat bahwa muat_semua_plugin() harus dipanggil sebelum buat_metode(), dan memutuskan bahwa validasi serta pemotongan saldo pada Tugas 3 harus memakai total (jumlah + biaya admin) agar saldo konsisten dengan biaya yang dibebankan.
